# Schools — ручная первоначальная настройка (принятое архитектурное решение)

Дата решения: 2026-10-28.
Статус: **реализовано начальное создание суперадминистратора и вход**.

## Режим установки
Только **ручной** режим. Автоматическую инициализацию администратора, автоматический режим установки и вывод одноразового установочного кода в терминал НЕ делать.

## Процесс
1. При открытии сайта PHP проверяет наличие пользователя `is_platform_admin=1`. Если такого пользователя нет, интерфейс предлагает создать глобального суперадминистратора (логин, пароль). Нет отдельного флага «система настроена».
2. Сервер создаёт случайный проверочный вызов (срок 30 минут); форма показывает случайное имя из пяти латинских букв, под которым оператор должен вручную создать пустой файл в корне проекта.
3. Сервер проверяет владение сервером по наличию пустого обычного файла с требуемым случайным именем в корне проекта (файлы корня не обслуживаются веб-сервером). Одной лишь загрузки `/setup` недостаточно для установки.
4. После проверки в одной атомарной операции создаётся первый пользователь с `is_platform_admin=1`, пароль хешируется Argon2id; новый суперадминистратор сразу входит в систему. Проверочный файл удаляется/инвалидируется.
5. Доступность формы определяется исключительно наличием суперадминистратора. Если суперадминистраторов нет (в том числе после удаления), создание первого вновь доступно при подтверждении владения сервером через файл.
6. Существующая БД и школы при будущей интеграции должны сохраниться. Первому суперадминистратору не требуется приглашение/членство для управления школами.

## Пользователи после первоначальной настройки
- Пользователь `users` уникален для всей платформы по `username`; человек сам вводит логин, а интерфейс предлагает свободные варианты, проверяемые сервером. Email не обязателен.
- Связь `memberships` допускает одного пользователя в нескольких школах. При регистрации по приглашению он вступает только в указанную школу, на указанный этап, с указанной ролью. В будущем типы приглашений: личное и общее с лимитами и сроками. Обычным пользователям статус глобального суперадминистратора не присваивается.
- Принятие приглашения, создание аккаунта и членства — атомарная транзакция; этап должен принадлежать школе приглашения.

## Защита от ошибочной реализации
- Не создавать публичный вход `register as admin` и не давать права первому случайному посетителю.
- Не генерировать или показывать секретные данные в stdout при автоматическом деплое.
- Не хранить установочный ключ, хеш пароля или готовую production-БД в репозитории.
- Не вводить флаг установки; защищаться от параллельных запросов при создании суперадминистратора.
